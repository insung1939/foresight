# 요구사항 점검 — 중간발표 교수님 피드백 반영 (2026-11-28)

중간발표 뒤 교수님이 기말 최종발표 채점 기준으로 짚어 준 항목을 그대로 표로 옮기고, 지금 상태와 기말까지 할 일을 적는다.
앱 안에서는 **데이터 페이지(`#/data`) 맨 위 '✅ 요구사항 점검표'** 가 같은 내용을 서버에 직접 물어본 값과 함께 보여 준다.

## 1. 기능적 요구사항

| 항목 | 교수님 말씀 | 지금 | 증거(어디서 보나) | 기말까지 |
|---|---|---|---|---|
| 데이터 · 신뢰성·정확성 | 믿을 수 있는 데이터 · 변경 반영 확인 | hindsight 원천 읽기만, 끊긴 종목 제외, 빈 주 직전 종가, 시점 단서 지우기. ✅ **갱신 때마다 원천 대조**(무작위 12종목×2주, hindsight 의 그 주 마지막 종가 = 시즌 팩 주봉, 첫 실행 24/24) · ✅ **갱신 기록**(언제, 어떤 주가 새로 들어왔는지) | 데이터 페이지 '🔄 데이터 갱신 기록 · 정합성' | 몇 주 쌓인 기록 |
| 데이터 · 지속가능성·주기 | 매일·실시간 등 | ✅ **매주 일요일 07:00 자동 갱신**(`.github/workflows/data-weekly.yml`): hindsight → 시즌 팩·검색 색인 재생성 → 품질 관문(`scripts/check_pack.py`) → 테스트 → 통과할 때만 `pack.enc` 커밋 → Render 자동 재배포. 실패하면 이전 데이터로 계속 서비스. 종목 순서를 지키고 판은 종목 id 로 다시 연결해 진행 중인 판이 안 깨짐 | `/v1/health` 의 `data.lastWeek`·`stale`, Actions 기록 | 몇 주 돌린 기록(주 수·색인 증가 표). 실시간 시세는 '과거를 다시 사는' 구조라 쓰지 않음 |
| 데이터 · 시각화 | 시각화 | 화제 광장, 주봉 차트, 결산 곡선, 분석 5개 | 플레이 화면, 데이터 페이지 | 플레이 기록이 쌓이면 '사람 vs 유튜버' 분석 차트 보강 |
| 아키텍처 | UI·백엔드·DB, 얼마나 견고한지 | React(Vercel) → FastAPI(Render) → Supabase Postgres+pgvector → Gemini. 미래 가격은 서버만, 랭킹 서버 재계산, AI 실패 시 규칙 답, ✅ DB 순간 끊김 → 503+Retry-After, 화면은 502·503·504 를 1.5→3→6초 자동 재시도(GET 은 네트워크 오류도) | 발표 10장, `/v1/health`(DB 응답 ms 포함) | 장애 시나리오 시연(AI 키 없음 / DB 끊김 → 게임은 계속) 녹화 |
| **의미 있는 시나리오 (제일 중요)** | 대상이 일반인이면 쉬워야 · 구체성(전문성·니즈) | 주린이 대상. **페르소나·하루 시나리오·니즈→기능 표**(팀 페이지 02) · **타임슬립 이야기**(그림) → 1분 게임 방법 → 8주 연습 → 12주 본 시즌. **쉬운 모드(기본)**: 금액 버튼 한 번으로 사고팔기, '이번 주 할 일' 한 줄, 공매도·전략 카드·수량 입력·멘탈 구간 효과는 고수 모드로. 인생 사건 14개마다 '💡 실제로는'(적립식·비상금·리딩방·생존 편향·물타기·미공개 정보 등) | 홈 첫 방문, 결산 엔딩 | 사용성 테스트(처음 하는 사람 5명 이상): 설명 없이 첫 판 끝내는 비율·시간 |
| UI/UX · 반응형 | 반응형이 잘 동작하는지 | 휴대폰 390px ~ 데스크톱, 바텀시트, 엄지 영역 버튼, 3D 품질 자동 조절 | 발표 6장 휴대폰 4화면 | 기기별(아이폰·갤럭시·태블릿·PC) 스크린샷 표 |
