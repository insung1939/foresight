# 성능·보안 등 비기능 요구사항

평가 항목 "성능·보안 등 기타 비기능적 요구사항(10%)": 응답 속도·비용, API 키·개인정보 보호, 적용·점검 내용, 최적화 전후 결과와 남은 한계.
숫자는 2026-11-14 로컬(맥북, SQLite)에서 직접 잰 값. 배포 뒤 Render·Supabase 에서 다시 잰다(데이터 페이지 '응답 속도' 칸이 실시간으로 보여 줌).

## 최적화 전후

| 무엇 | 전 | 후 | 어떻게 |
|---|---|---|---|
| 게임 시작 때 받는 데이터 | 1.2 MB(첫 프로토타입: 문제 150개 + 정답 파일 통째로) | 0.4 KB | 정답을 서버로 옮기고 단계별로 볼 수 있는 것만 보냄 |
| 카드 한 장 | (위 파일에 포함) | 약 3 KB, 3~5 ms | 열 때 한 장씩 → 안 연 카드는 개발자도구로도 못 봄 |
| 첫 화면 JS | 420 KB (gzip 141 KB) | 340 KB (gzip 116 KB, −18%) | 리포트·랭킹·데이터·팀 페이지 코드 분할(React.lazy) |
| 실시간 랭킹 | 4.0 KB · 6.8 ms | 0.8 KB(gzip) · 1.5 ms | 2초 캐시 + gzip. 여러 화면이 4초마다 불러도 DB 계산은 2초에 한 번 |
| 데이터 페이지 | 7 KB | 약 2.3 KB(gzip) | GZipMiddleware(800바이트 넘는 응답) |

측정 방법: `curl -w "%{size_download} %{time_total}"`, `npm run build` 출력, 서버 `X-Response-Time` 헤더.

## 응답 속도 측정(운영 중)

`api/app/ops.py` 미들웨어가 라우트별 최근 500건의 처리 시간을 모아 p50·p95 를 낸다 → `GET /v1/meta` 의 `perf` → 데이터 페이지 '응답 속도', 팀 페이지 '성능·보안'.
모든 응답에 `X-Response-Time` 헤더.

## 비용

- AI 판단(문제 452개)은 미리 한 번 배치(`scripts/ai_judge.py`) → 게임 중 호출은 플레이어가 질문할 때만.
- 질문: 라운드당 3번, 200자. 한 사람(IP + 기기 표식) 1분 12번, 서버 전체 1분 60번(넘으면 429 + Retry-After). 새 게임 1분 20번, 그 밖의 POST 600번(리플레이 하루 진행 포함).
- 강의실처럼 같은 와이파이(한 IP)에 여러 명이 있어도 서로 막지 않게 IP 만이 아니라 기기 표식까지 묶어 센다.
- Gemini 무료 등급 · Render·Vercel·Supabase 무료 플랜. 질문 1번 평균 토큰은 `ai_logs` 에 쌓여 데이터 페이지에 표시.

| 남용 | 사람별 요청 한도(429), AI 서버 전체 상한, 입력 길이 제한 | 테스트 |

| DB 연결 | AI 응답을 기다리는 동안 DB 연결을 돌려줌(풀 고갈 방지) | 코드 리뷰 |

| 브라우저 | CORS 허용 주소 제한, `nosniff`, `X-Frame-Options: DENY`, 게임 응답 `no-store` | 테스트 |
| AI 출력 | 6가지 검증(이름 노출·지어낸 숫자·권유 등), 실패 시 숨김 | `docs/ai.md`, `docs/ai-eval.md` |

## 남은 한계

- Render 무료 서버는 15분 쉬면 잠든다 → 첫 접속 30초 안팎. 화면에 '서버 깨우는 중' 안내, 발표 직전 미리 접속.
- 요청 한도·게임 잠금·응답 시간 기록은 서버 메모리(서버 한 대 가정). 여러 대면 Redis·DB 잠금 필요.
- 차트 카드의 코스피 60일 흐름을 실제 지수와 맞춰 보면 날짜를 추정할 수는 있다(차트를 지수화해 숫자는 숨겼지만 모양은 남음).
- 오늘의 챌린지 '첫 판만 순위'는 기기 표식·닉네임·계정 기준이라, 기기 기록을 지우면 피할 수 있다(로그인 사용자 기준이 가장 확실).
- 공시 계약명 같은 가리기 어려운 단서는 남을 수 있음(회사를 알아봐도 미래 주가는 모름).
