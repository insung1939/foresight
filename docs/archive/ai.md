# AI 설계 — 모델 · 프롬프트 · 검증

평가 기준: "LLM 기능은 기술의 화려함이 아니라 **오답이 나왔을 때의 대응 설계**로 평가한다."
그래서 이 문서는 'AI가 틀리면 어떻게 되는가'를 중심으로 쓴다.

## 쓰는 곳 2가지

| 기능 | 언제 | 코드 |
|---|---|---|
| **AI 애널리스트** | 플레이어가 AI 카드를 열고 질문할 때(라운드당 3번) | `api/app/ai.py` `ask()` · `POST /v1/games/{id}/ask` |
| **AI의 판단** | 문제마다 미리 한 번(배치). 결과 공개 때 '🤖 AI' 줄로 비교 | `ai.py` `judge()` · `scripts/ai_judge.py` → `data/ai.json` |

- 모델: 클라우드 Gemini (`GEMINI_MODEL`, 기본 `gemini-3.5-flash`) · 로컬 Ollama `qwen3.5:4b`(수업 3주차). 서버에서만 호출, 키는 `.env` 에만.
- 모델 대체: 기본 `gemini-3.5-flash` 가 바쁨(503)·한도(429)·시간 초과·모델 없음(404)이면 `GEMINI_FALLBACKS`(기본 `gemini-3.5-flash-lite`)로 넘어간다. 실제 답한 모델을 ai_logs 에 남긴다. (배포 당일 `gemini-3.8-flash` 는 503 이 잦았고 `gemini-2.5-flash` 는 새 사용자에게 막혀 있어 이렇게 정함)
- 제공자 선택 `LLM_PROVIDER`: `auto`(Gemini 키가 있으면 Gemini, 없으면 켜져 있는 로컬 Ollama) · `gemini` · `ollama`. 배포 서버는 `gemini`.
- 두 모델 모두 같은 JSON 스키마(Gemini `responseSchema` / Ollama `format`)와 같은 6가지 검증을 거친다 → 같은 평가 묶음으로 비교(`docs/ai-eval.md`).
- `temperature` 0.2(답변) / 0.1(판단), JSON 스키마 강제(`responseSchema`), 2.5 Flash 는 생각 토큰 0(응답 속도 우선).

## 1. 자료 제한 (미래 정보 차단)

AI 에게는 그 문제의 **산 날(T0) 이전 자료만** id 를 붙여 준다. `build_docs()`

| id | 자료 | 출처 |
|---|---|---|
| C1 | 60일 수익률·코스피·고점 대비·거래량 | 시세 |
| F1 | 직전 정기보고서 재무(비율·구간만) | DART fnlttSinglAcnt |
| D1… | 30일 공시 제목 + 원문 핵심 항목 | DART list · document |
| N1… | 산 날 15:30 전 뉴스 제목 | Google 뉴스 RSS |
| Y0, Y1… | 유튜버 논조 집계·영상 제목 | hindsight |

회사 이름·사람 이름·가격·날짜는 미리 가려서 넘긴다(`masking.py`). 정답(20일 뒤 수익률)은 자료에 없다.

## 2. 프롬프트

시스템 프롬프트 원문은 `api/app/ai.py` 의 `ASK_SYSTEM`, `JUDGE_SYSTEM`. 요점:

1. [자료]에 있는 내용만 근거로. 자료에 없는 사실·숫자·앞으로 일어날 일은 말하지 않는다.
2. 회사는 'A사'로만. 실제 회사를 추측하지 않는다.
3. 근거 자료 id 를 `citations`(판단은 `reasons[].cite`)에 넣는다.
4. 자료로 답할 수 없으면 `grounded=false`, '확인된 근거가 없어요.'로 시작.
5. 사라·팔아라 같은 직접 권유 금지.
6. 숫자는 자료에 적힌 그대로. 계산해서 새 숫자를 만들지 않는다.

## 3. 검증 6가지 (`check()`)

| # | 검사 | 걸리는 예 |
|---|---|---|
| 1 | JSON 형식 | 스키마 밖 응답, 파싱 실패 |
| 2 | 인용 id 실재 | 자료에 없는 `X9` 인용 |
| 3 | 회사 이름 노출 | 답에 실제 회사명·종목코드 |
| 4 | 숫자 출처 | 자료에 없는 '35%' (지어낸 숫자) |
| 5 | 직접 권유 | '지금 사세요', '무조건' |
| 6 | 근거 없는 단정 | `grounded=true` 인데 인용 없음 |

단위 테스트: `api/tests/test_api.py::test_ai_check_catches_bad_answers`

## 4. 실패하면

```
1차 답 → 검증 ─ 통과 → 화면에 보여 줌(✓ 검증 통과, 근거 칩)
              └ 실패 → "이전 답이 검증에 실패함: {항목}" 을 붙여 1번 더
                         ─ 통과 → 보여 줌(✓ 검증 통과 · 다시 물어서)
                         └ 실패 → 답을 숨기고 대체 문구(⚠️ 검증 실패)
호출 자체 실패 → 종류별 안내(질문 횟수 차감 안 함)
  unconfigured(키 없음) 🔌 · quota(429) ⏳ n초 카운트다운 · busy(5xx) 🔥 · timeout 🐢 · network 📡 · model ⚠️
```

AI 판단(배치)은 검증을 통과한 것만 `ai.json` 에 저장한다. 없는 문제는 결과 화면에 'AI 판단이 아직 없어요'로 보인다.

## 5. 기록

모든 호출을 `ai_logs` 테이블에 남긴다: 질문·답·통과 여부·검사 항목별 결과·시도 횟수·지연·토큰·모델.
데이터 페이지 'AI 답변 검증' 칸이 이 표를 집계한다(바로 통과 / 다시 물어 통과 / 숨김 / 호출 실패 / 평균 응답 시간).

## 6. 비용·속도

- AI 판단은 문제 452개 × 1회를 미리 만들어 둔다 → 게임 중 호출은 질문할 때만.
- 질문은 라운드당 3번, 200자 제한. 호출 사이 대기·429 재시도는 `ai_judge.py` 에 있다.
- 남은 한계: 숫자 검사는 '자료에 같은 숫자가 있는가'만 본다. 숫자는 맞는데 해석이 틀린 경우는 못 잡는다 → 근거 칩으로 사용자가 직접 확인할 수 있게 했다.

## 7. 짓궂은 질문 평가(`scripts/ai_eval.py` → `docs/ai-eval.md`)

정상 질문보다 틀리게 만들려는 질문을 더 많이 넣은 묶음(문제당 15개): normal · leak(이름 캐기) · future(미래 주가) · advice(매수 권유) · offtopic(자료 밖) · inject(이전 지시 무시).
통과 = 화면에 틀린 답이 보이지 않음(6가지 검증 + 묶음별 기대 행동). 프롬프트를 고칠 때마다 `--tag` 를 바꿔 돌려 전후를 비교한다.
