# 예상 질문과 답 (질의응답 5분 대비)

평가 기준 "코드의 양보다 전체 흐름을 설명하고 AI 결과를 검증·수정한 근거". 누가 받아도 답할 수 있게, 짧게 + 근거 위치.

## 시스템·AI

**Q1. RAG 를 썼나요? pgvector 는요?**
'시점 제한 RAG'다. 질문이 오면 그 문제의 산 날 이전 문서만 꺼내(종목·날짜 메타데이터 필터) id 를 붙여 넣고, 답에 근거 id 를 달게 한다. 한 문제 문서가 20개 안팎이라 유사도 검색보다 '미래 문서를 절대 섞지 않는 필터'가 정확도·공정성에 더 중요했다. 벡터 검색은 '비슷했던 과거 사례 찾기'로 확장할 계획. → `api/app/ai.py` build_docs

**Q2. AI 가 틀리면 어떻게 되나요?** (평가 핵심)
보여 주기 전 6가지 자동 검사(형식·인용 id 실재·회사명 노출·자료에 없는 숫자·직접 권유·근거 없는 단정). 실패하면 실패 항목을 알려 주고 1번 더, 또 실패하면 답을 숨기고 이유를 보여 준다. 호출 실패는 종류별(한도·시간 초과·서버 바쁨…) 안내, 질문 횟수는 깎지 않는다. 모든 호출은 ai_logs 에 남고 데이터 페이지에 통과율. → `docs/ai.md`

**Q3. 검증을 어떻게 믿나요?**
짓궂은 질문 묶음(이름 캐기·미래 주가·매수 권유·지시 무시·자료 밖)을 돌려 '틀린 답이 화면에 보였는지'를 잰다. 로컬 모델(qwen3.5:4b)과 Gemini 를 같은 묶음으로 비교. → `scripts/ai_eval.py`, `docs/ai-eval.md`, 팀 페이지 AI 칸

**Q4. 숫자 검사의 한계는?**
'자료에 같은 숫자가 있나'만 본다. 숫자는 맞는데 해석이 틀린 경우는 못 잡는다 → 근거 칩으로 원문을 바로 확인하게 했다.

**Q5. 왜 로컬 LLM 도 붙였나요?**
키·한도·네트워크가 없어도 개발·평가를 돌리기 위해(수업 3주차 Ollama). `LLM_PROVIDER=auto` 면 Gemini 키가 있으면 Gemini, 없으면 로컬. 같은 검증을 거친다. 배포 서버(Render)는 Gemini.

**Q6. 정답이 화면에 안 새는 걸 어떻게 증명하나요?**
정답은 서버만 갖고 단계마다 볼 수 있는 것만 보낸다. 테스트가 10라운드 내내 모든 응답에 회사명·코드·날짜·내부 필드가 없는지, 리플레이 중 매일 '오늘까지'의 주가만 오는지 검사한다. → `api/tests/test_api.py`

**Q7. 동시에 여러 명이 하면?**
요청 한도는 IP+기기 기준이라 같은 와이파이의 여러 명이 서로 막지 않는다. 같은 게임의 동시 요청은 게임별 잠금 + DB 유니크 인덱스로 한 번만 처리(코드 리뷰로 버그를 찾아 고침, 테스트). AI 응답을 기다리는 동안 DB 연결을 돌려준다.

## 데이터

**Q8. 데이터는 어디서? 품질은?**
지난 학기 hindsight(유튜브 언급 53,409건 + 시세 + 공시)를 읽기 전용으로, DART 재무·원문, Google 뉴스를 더했다. 점검 스크립트가 미래 정보 0, 회사명 노출 0, 정답 불일치 0, 절대 금액 0 을 확인(테스트). → 데이터 페이지 '데이터 품질 점검'

**Q9. 유튜버 '오른다/내린다'는 어떻게 판정했나요? 정확한가요?**
hindsight 가 영상 제목을 단어 사전으로 분류한 것. 제목만 보므로 반어·풍자는 틀릴 수 있다(한계로 명시). 그래서 유튜버 카드에 제목 원문을 같이 보여 준다.

**Q10. 2026년이 급락장이라 '유튜버가 틀렸다'는 결론이 편향된 것 아닌가요?**
맞는 지적. 그래서 시장(코스피)과 나란히 비교하고, 문제를 오른/내린/보합으로 섞어(152/200/100) '안 사면 이기는' 게임이 되지 않게 했다. 유튜버 평가도 기간 전체 성적이 아니라 그 시점까지의 적중률을 보여 준다.

**Q11. 자극어 분석은 인과관계인가요?**
아니다, 상관관계다. '놓치면'이 들어간 영상 뒤 성과가 나빴다는 관찰이고, 게임에선 판단 근거가 아니라 주의 표시(🔥)로만 쓴다.

**Q12. 회사 이름을 가려도 검색하면 찾지 않나요?**
그래서 이름뿐 아니라 사람 이름·날짜·가격·계약명·계약 상대·절대 금액(구간으로)을 가렸다. 그래도 차트 모양·업종 단서는 남는다. 회사를 알아도 '그 뒤 20일'은 모른다는 게 게임의 전제.

## Needs·시장

**Q13. 왜 '게임'인가요? 효과가 있나요?**
실전은 돈을 잃고 결과가 몇 주 뒤에 나온다. 게임은 5분 안에 판단 → 결과 → 피드백(유튜버·AI·시장 비교, 성향 리포트)을 반복한다. 효과는 설문(도움 정도, 느낀 점)과 '같은 사람의 n번째 판 적중률'로 측정한다. → 데이터 페이지 분석 6

**Q14. 근거가 되는 시장 숫자는?**
개인 주식 투자자 1,442만 명(예탁결제원), 주식 정보 얻는 곳 1위 유튜브 37.4%(피앰아이 조사). 출처: `docs/needs.md`

**Q15. 경쟁 서비스와 차이는?**
모의투자는 지금 시장에서 몇 주를 기다리고, 유튜브·커뮤니티는 말한 사람의 과거 성적을 안 보여 준다. 우리는 실제 과거 + 즉시 채점 + 유튜버 성적 + 근거 있는 AI.

**Q16. 투자 권유로 오해받지 않나요?**
과거 데이터 학습용, 모든 페이지에 면책 문구, AI 는 사라·팔아라를 말하면 검증에서 막힌다.

## UI/UX·비기능

**Q17. 사용성 개선은 어떻게 했나요?**
발견→원인→수정→확인 24건(`docs/ux-log.md`). 예: 휴대폰에서 비중 버튼까지 스크롤 → 아래 고정 패널, 정적인 진행 → 20일 리플레이, 운에 좌우되는 랭킹 → 오늘의 챌린지.

**Q18. 로딩·오류·빈 결과는?**
스켈레톤 + '서버 깨우는 중', 오류는 다시 시도·이어하기(진행은 서버 저장), 빈 결과는 '공시 없음도 정보', 랭킹 비면 '첫 1등 되기', AI 실패는 종류별 안내.

**Q19. 성능·비용 최적화는?**
게임 시작 1.2MB → 0.4KB(정답을 서버로), 첫 화면 JS gzip 141→116KB(코드 분할), 랭킹 6.8→1.5ms(2초 캐시). AI 판단은 미리 배치, 질문만 실시간. → `docs/perf.md`

**Q20. 개인정보는?**
로그인은 선택(구글), 서버엔 로그인 확인용 id 와 닉네임만(이메일 저장 안 함). 설문은 객관식만. 키는 서버 환경 변수, 정답 파일은 암호화해서 공개 저장소에.
